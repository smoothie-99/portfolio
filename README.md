# 강한솔 | Backend Developer

> **기계의 흐름을 설계하던 시선으로, 이제는 시스템의 흐름을 설계합니다.**

기계설계공학을 전공하고 2차전지 믹싱 장비 제조 현장에서 **장비 설계, BOM 작성, 부품 발주, 현장 이슈 대응**을 경험했습니다.

현장에서 문제의 원인을 확인하고 구조를 수정하던 경험을 바탕으로, 지금은 **요구사항을 데이터와 API 구조로 구체화하고 실제 동작까지 검증하는 백엔드 개발자**를 목표로 하고 있습니다.

단순히 기능을 구현하는 데서 끝내지 않고,

```text
문제 정의 → 구조 설계 → 구현 → 데이터 확인 → 테스트 → 배포
```

까지 이어지는 전체 흐름을 이해하고 직접 확인하는 개발을 지향합니다.

## About Me

### 현장을 이해하고, 흐름을 설계합니다.

제조 현장에서 설계 업무를 담당하며 도면만 보고 문제를 판단하기보다 실제 설치 환경과 작업 조건을 확인하는 방식으로 문제를 해결했습니다.

백엔드 개발에서도 같은 방식으로 접근합니다.

- 요구사항에서 필요한 데이터와 기능을 먼저 구체화합니다.
- API와 데이터의 흐름을 기준으로 시스템 구조를 이해합니다.
- Postman과 실제 응답 데이터를 통해 구현 결과를 검증합니다.
- 문제가 발생하면 현상보다 원인을 먼저 확인합니다.
- 구현 이후에도 연동·테스트·배포 결과까지 확인합니다.

### 제가 가진 차별점

`01` **현장 기반 문제 해결**

기계설계 및 제조 현장 경험을 바탕으로 실제 사용 환경과 프로세스를 고려해 문제를 정의합니다.

`02` **데이터와 API 중심 사고**

화면에 필요한 데이터가 어디에서 생성되고 어떻게 전달되는지 추적하며 API와 데이터 구조를 이해합니다.

`03` **협업을 통한 문제 구체화**

프론트엔드·백엔드·현장 담당자와 문제 상황을 공유하고 실행 가능한 해결 방법으로 구체화합니다.

`04` **구현 이후까지 확인하는 습관**

기능 구현 자체보다 실제 요청·응답, 데이터 저장, 연동, 배포 결과가 정상적으로 동작하는지 확인합니다.

**담당 역할**: Infra · Backend · AI Integration

#### 주요 문제

```text

                    ↓
            사람이 지정한 가중치

               파지 점수 계산
```


Java Swing으로 매장·포장 선택부터 메뉴·옵션·장바구니·결제 완료까지 이어지는 키오스크 주문 흐름을 구현하고 화면 상태와 타이머 문제를 개선했습니다.

#### 주요 구현 및 개선

- 버거·사이드·음료·디저트 메뉴와 세트 옵션 구성
- 선택한 사이드·음료·소스 정보를 장바구니 데이터와 일치하도록 관리
- 메뉴 유형이 아니라 실제 추가 선택 여부를 기준으로 옵션 문구 표시
- 주문 확인 목록의 높이를 데이터에 맞게 계산하고 마우스 휠 스크롤 지원
- 유휴 타이머를 `JFrameKiosk`에서 하나의 상태로 관리
- 패널 전환 시 타이머의 표시 여부와 Z-order를 중앙에서 제어
- 사용자 입력이 발생하면 타이머를 초기화하고 시간 초과 시 홈으로 복귀
- 결제 화면 → 결제 완료 화면 → 홈으로 이어지는 Timer 기반 전환 구성
- 화면을 벗어날 때 실행 중인 Timer를 정지해 지연 이벤트가 다른 화면에 영향을 주지 않도록 처리

```text
매장/포장 선택 → 메뉴·옵션 → 장바구니 → 주문 확인
        → 결제 수단 → 결제 처리 → 결제 완료 → Home
```

**Tech**: `Java` `Swing`

**이 경험에서 보여주고 싶은 것**

각 화면을 개별적으로 구현하는 데서 끝내지 않고, **공통 상태·화면 전환·타이머 생명주기를 함께 관리해야 전체 주문 흐름이 안정적으로 동작한다는 점**을 경험했습니다.
